# Наследие печати

Небольшой одиночный 2D action-adventure прототип на **Phaser 3.90.0, TypeScript и Vite**. Два рыцаря из враждующих родов входят в разрушенное святилище и вместе сражаются с демоном. Камера строго сверху; окружение и персонажи — оригинальная процедурная пиксельная графика.

Это законченный демонстрационный отрывок, а не будущая сюжетная игра на 10–15 часов. Баланс предварительный.

## Публикация через GitHub Pages

Сайт рассчитан на адрес **https://hidek1ch.github.io/dota-spell-letter-hunt/**. В `vite.config.ts` указан `base: '/dota-spell-letter-hunt/'`, поэтому ресурсы сборки загружаются из папки проекта.

GitHub Pages уже настроен. Чтобы опубликовать обновление:

1. Слейте ветку с изменениями в `main`.
2. На вкладке **Actions** дождитесь успешного запуска **Deploy game to GitHub Pages**. После завершения откройте адрес сайта выше.

При первой настройке другого репозитория выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**.

Далее каждый push в `main` автоматически выполняет `npm ci && npm run build` на Node.js 24 и публикует **только папку `dist`**. Возможен ручной запуск через **Actions → Deploy game to GitHub Pages → Run workflow**, когда workflow уже находится в основной ветке. Публиковать исходники в ветку `gh-pages` не требуется.

Проверка локальной сборки: `npm ci && npm run build`, затем `npm run preview`. Открывайте путь `/dota-spell-letter-hunt/` на адресе локального сервера. Этот префикс нужен и для `npm run dev`; для браузерного теста задайте `SEAL_URL=http://127.0.0.1:5173/dota-spell-letter-hunt` без завершающего слеша.

GitHub Actions использует встроенный `GITHUB_TOKEN`: дополнительные токены и секреты не требуются. Выбор источника Pages и первый успешный запуск workflow выполняются на GitHub; локальная успешная сборка сама по себе сайт не публикует. Портативный `npm run portable` продолжает создавать автономный HTML без зависимости от URL Pages.

## Запуск на ПК без установки

Готовый вариант для ПК: откройте файл `release/nasledie-pechati-PC.zip` на GitHub и нажмите **Download raw file**. Распакуйте архив, затем откройте `START_GAME.html` в Chrome или Edge. Исходники можно получить через **Code → Download ZIP** на странице этой ветки.

Папка `release/` содержит `START_GAME.html` — самодостаточную версию игры. Сохраните её на компьютер и откройте двойным щелчком в Chrome или Edge. Расширение файла должно быть `.html`, а не `.html.txt`. Интернет, Node.js и локальный сервер для этой версии не нужны. В `nasledie-pechati-PC.zip` находятся тот же HTML, краткая инструкция и лицензии.

Воспроизводимая сборка: `npm run portable`. Генератор `scripts/portable.mjs` встраивает JS, CSS, значок и уведомления о лицензиях в один файл. Дополнительная проверка: `python3 tests/portable_smoke.py`. Управляемый Chromium в этой облачной среде запрещает адреса `file://`; при таком ограничении тест проверяет тот же HTML из памяти без сервера и внешних ресурсов. Это не проверка двойного щелчка на реальном ПК. Для этой необязательной проверки нужны Playwright и Chromium.

## Запуск

Нужен Node.js **20.19+ или 22+** и npm. Текущая сборка проверена на Node.js 24.

```bash
# В облачной среде проект расположен здесь; на ПК перейдите в распакованную папку.
cd /workspace/dota-spell-letter-hunt
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. По умолчанию сервер использует порт 5173 и слушает все интерфейсы. Для локальной разработки на своём компьютере достаточно открыть его в браузере. Если порт уже занят, Vite может выбрать следующий — смотрите вывод команды.

Сборка и просмотр собранной игры:

```bash
npm run build
npm run preview
```

`npm run build` сначала проверяет TypeScript, затем создаёт `dist/`. `npm run preview` запускает локальный сервер для этой сборки, обычно на порту 4173. Не открывайте `dist/index.html` двойным щелчком: для ES-модулей нужен HTTP-сервер.

Для запуска без npm и сервера используйте `release/START_GAME.html`. Обычная сборка `dist/` ожидает путь `/dota-spell-letter-hunt/`: для её локального просмотра используйте `npm run preview`, а при размещении на другом статическом сервере монтируйте содержимое `dist/` под этим префиксом. Аккаунты, сервер игры, ключи API и внешние графические или звуковые сервисы не требуются. После установки зависимостей сборка и локальная игра обходятся без подключения к интернету; шрифты системные, графика и звук создаются в приложении. Это не PWA: офлайн-работа здесь означает доступность локального сервера, а не гарантированный запуск ранее закрытой вкладки из браузерного кеша.

## Исследование замка

В верхней части главного меню нажмите **«Исследовать замок»**. Откроется самостоятельный режим с двумя связанными локациями: тренировочный двор **1920×1280** и оружейная **1280×960**. Камера следует за героем и останавливается у границ; стены, мебель и смотритель имеют коллизии.

1. Герой появляется в центре двора. Подойдите к смотрителю справа и нажмите **E / Enter**: он укажет путь в оружейную.
2. Идите к двери в центре северной стены. Когда появится **«E — Войти в оружейную»**, нажмите E / Enter. Само пересечение порога переход не запускает. Во время короткого затемнения управление и повторное взаимодействие блокируются.
3. В оружейной осмотрите стойки, доспехи, столы и сундук. Нажмите **M** или кнопку **«Карта»**: миникарта показывает текущее помещение, мебель, двери, смотрителя, героя и область камеры. С открытой картой можно продолжать движение.
4. Для возвращения подойдите к южной двери и нажмите E / Enter. Герой появится у северного входа во двор; здоровье и снаряжение сохранятся между комнатами.

**WASD / стрелки** — движение; **E / Enter** — дверь или разговор; **M** — миникарта; **Esc** — пауза. На телефоне доступны стик слева, крупная кнопка E, карта и пауза справа. Пауза и кнопка **«В меню»** позволяют вернуться к главному экрану.

Новое исследование начинается со здоровья **100/100** и пустого списка снаряжения. Состояние хранится в памяти текущей сессии; подбор предметов и сохранение на диск не добавлены. Повторный выбор «Исследовать замок» в меню начинает новую сессию. Подробности устройства переходов и расширения карты — в [docs/CASTLE.md](docs/CASTLE.md).

## Как играть

1. В главном меню выберите сложность, режим таймера и звук. **«Начать путь»** ведёт в обучение; **«Сразу к печати»** пропускает двор и запускает сцену согласия хранителя перед боем с демоном.
2. Два противника во дворе — первый, учебный этап. Освойте движение, меч, уклонение и драконью силу. После победы над обоими откроется золотая арка на севере: пройдите между колоннами, и переход сработает автоматически. Рядом с аркой также можно нажать E / Enter или сенсорную кнопку ◇.
3. В сцене длительностью 10,5 секунды хранитель добровольно открывает доступ через кольцо. Главный герой становится проводником резонанса, **но не хранителем**: наследственный обряд прошёл союзник.
4. В бою избегайте отмеченных зон, атакуйте в моменты восстановления демона и сочетайте меч, драконью волну и совместный приём печати. Союзник сражается самостоятельно, помогает барьером и поддерживает связь кольца. Его гибель прекращает защиту и завершает попытку.
5. Победа и поражения ведут к внутриигровым анимированным сценам. Кат-сцены можно пропустить. После завершения доступны повторная попытка и возврат в меню.

Босс меняет фазы от потери здоровья. Время отдельно усиливает опасность и расходует целостность печати. Отмеченные на земле зоны — реальные телеграфы ударов; во время короткого уклонения действует неуязвимость. Обычное попадание также даёт короткую защиту от мгновенного повторного урона.

### Управление на компьютере

| Действие | Клавиши / мышь |
| --- | --- |
| Движение в восьми направлениях | WASD / стрелки |
| Направление взгляда и удара | К курсору мыши; без мыши — направление движения |
| Меч: одно нажатие — один удар | J / левая кнопка мыши |
| Уклонение | Space |
| Драконья способность | Q / K |
| Совместный приём кольца | L / R |
| Взаимодействие вне боя | E / Enter |
| Пауза | Esc |

**Одно нажатие J, ЛКМ или сенсорной кнопки — один удар.** Для комбо 1 → 2 → 3 сделайте три отдельных нажатия; удержание не повторяет удары. Во время текущего удара можно поставить в очередь только один следующий. После паузы между ударами цепочка начинается заново. Три удара различаются подготовкой, областью попадания и восстановлением.

Нажатие драконьей способности или кольца во время комбо сохраняется в коротком буфере ввода: при наличии ресурса и готовой перезарядке приём сработает в ближайшее окно восстановления. **В обучении кольцо ещё закрыто:** нажатие L объясняет, что нужно войти в арку. Оно открывается после согласия хранителя и работает только при живом союзнике. Драконья сила расходует отдельный ресурс; способности имеют перезарядку.

### Сенсорное управление

На мобильном экране доступны виртуальный стик слева, четыре кнопки справа: меч, уклонение, драконья сила и кольцо. Каждое отдельное касание меча даёт один удар; удержание не включает автоатаку. Отдельная кнопка взаимодействия заменяет E. Направление удара задаётся движением стика. Для меню, паузы и пропуска кат-сцен клавиатура не нужна.

Предпочтительна горизонтальная ориентация. Интерфейс учитывает safe-area, масштабирует мир без растяжения по осям и блокирует прокрутку при управлении. Звук активируется после пользовательского нажатия или касания; его можно выключить в меню.

### Сложность и таймер

Доступны три уровня: сюжетный, обычный и сложный. Это настройки баланса демонстрации, а не утверждённая числовая система всей игры.

- **Обычный режим: 15:00.** Каноническая продолжительность защиты печати в финальном сражении — ровно пятнадцать минут.
- **Режим демонстрации: 2:30.** Ускоренный тестовый таймер для короткого знакомства с боем и проверки поражения по времени. Он не меняет лор.

Во дворе HUD показывает выбранные **15:00 или 2:30**, сложность и подпись **«СТАРТ ОТСЧЁТА — У ДЕМОНА»**. Это ещё не бой с боссом: время заморожено. Отсчёт начинается только после сцены согласия хранителя, в бою с демоном; пауза и кат-сцены также его не расходуют. Один год Кровавого Завета — независимый сюжетный срок, не таймер этого боя.

## Развязки

- **Победа:** демон исчезает в пепле, повреждённая печать распадается, души прежних хранителей освобождаются. Герой разрушает кровавый кулон и теряет драконью силу. После сцен освобождения душ и разрушения кулона открывается короткий управляемый эпилог на рассвете: можно пройти рядом с союзником, затем завершить историю взаимодействием.
- **Поражение от урона:** демон разрывает связь, возвращает подаренную силу, побеждает хранителя и захватывает печать.
- **Поражение по времени:** защита гаснет, демон возвращает силу, побеждает хранителя, разрушает печать и освобождается. Это отдельная последовательность анимационных событий.

Поражения неканонические; повторная попытка позволяет пройти отрывок заново.

## Код и настройка

```text
src/
  main.ts                 # Phaser, масштабирование, запуск
  scenes/
    GameScene.ts          # игровой цикл, меню, HUD и кат-сцены
    WorldView.ts          # арена, спрайты, эффекты и слои отрисовки
  game/
    balance.ts            # HP, урон, скорости, тайминги, перезарядки
    model.ts              # типы персонажей и эффектов
    combat.ts             # симуляция боя, hitbox, AI, состояния и исходы
  exploration/
    CastleScene.ts        # две самостоятельные сцены двора и оружейной
    locations.ts          # размеры, стены, мебель, двери и точки появления
    types.ts              # типы локаций и общего состояния героя
    movement.ts           # нормализация движения и коллизии
    TransitionManager.ts  # переходы и общее состояние между комнатами
    LocationView.ts       # отрисовка окружения и героя
    CastleHud.ts           # здоровье, снаряжение, подсказки, миникарта
    style.css              # интерфейс исследования
  art/generate.ts         # генератор оригинальных текстур и кадров спрайтов
  systems/
    Input.ts              # клавиатура, мышь и сенсорные элементы
    Audio.ts              # процедурные звуки Web Audio
  style.css               # интерфейс и адаптация
public/                   # статические файлы
scripts/
  test.mjs                # запуск всех TypeScript-наборов tests/*.test.ts
  portable.mjs            # автономная HTML-сборка
tests/
  combat.test.ts          # автоматические проверки боевой симуляции
  exploration.test.ts     # геометрия, движение, переходы и сохранение состояния
  castle_browser.py       # браузерный маршрут двор → оружейная → двор
  browser_smoke.py        # полный игровой цикл и сенсорный ввод
  player_flow.py          # клики, удержание, комбо, настройки и урон печати
  portable_smoke.py       # автономная HTML-версия
```

Боевая логика отделена от Phaser: её можно тестировать без GPU и браузера. Демон использует явные состояния преследования, подготовки, атаки, восстановления, реакции на попадание, перехода фазы и поражения. Четыре семейства атак — широкий взмах, направленная волна, опасная зона и рывок. Союзник управляется собственной логикой и не рассчитан на самостоятельную победу без участия игрока.

Числовой баланс меняйте в `src/game/balance.ts`. Для расширения графики изменяйте генератор кадров, сохраняя единый размер пикселя и соглашение о направлениях/кадрах. Обновляйте автоматические проверки при изменениях боевых правил.

## Проверка

```bash
npm test
npm run build
npm run dev
```

`npm test` через `scripts/test.mjs` запускает все файлы `tests/*.test.ts` на Node.js с `tsx`, включая боевую логику и исследование замка. Они дополняют, но не заменяют браузерную проверку ввода, отрисовки, звука и сцен.

Для ручной приёмки пройдите меню → обучение → открытую арку → сцену кольца → бой. Также проверьте уклонение, обе способности, паузу, повторную попытку и отдельный вход через «Сразу к печати». Отдельно проверьте победу, поражение от урона и истечение короткого таймера: анимационные последовательности должны отличаться. На сенсорном экране проверьте одновременное движение и атаку, взаимодействие и пропуск сцен.

Браузерный сценарий `tests/browser_smoke.py` проверяет путь от настоящих кнопок меню через обучение и северные ворота, сцену кольца и бой на **сюжетной сложности**, затем освобождение душ, кулон, управляемый рассвет и экран результата. Контроллер отправляет клавиатурные и указательные события, а тестовый стенд ускоряет игровые кадры. В сценарий включены пауза, повторная попытка и возврат в меню. Для двух проигрышей стенд отдельно устанавливает нулевое здоровье или истекающий таймер, затем проверяет разные кат-сцены и экраны результата; это не проверка ручного ожидания пятнадцати минут в браузере.

Мобильный сценарий **844×390** проверяет отсутствие горизонтального переполнения и одновременное движение стиком и отдельные удары двумя касаниями через Chromium CDP. Это не проверка реального iPhone или Safari.

Для повторения дополнительного браузерного теста нужны Python, пакет `playwright` и установленный Chromium. Это необязательные инструменты проверки, они не нужны игроку или сборке. Оставьте `npm run dev` работающим в другом терминале, затем из корня проекта выполните:

```bash
python3 -m venv /tmp/seal-browser-tests
/tmp/seal-browser-tests/bin/pip install playwright
SEAL_URL=http://127.0.0.1:5173/dota-spell-letter-hunt \
  /tmp/seal-browser-tests/bin/python tests/browser_smoke.py

SEAL_URL=http://127.0.0.1:5173/dota-spell-letter-hunt \
  /tmp/seal-browser-tests/bin/python tests/player_flow.py

# Для режима замка; укажите порт реально работающего dev/preview-сервера.
SEAL_URL=http://127.0.0.1:4180/dota-spell-letter-hunt \
  /tmp/seal-browser-tests/bin/python tests/castle_browser.py
```

Тест запускает `/usr/bin/chromium`; `SEAL_URL` должен включать префикс `/dota-spell-letter-hunt` без завершающего слеша. При других путях задайте переменные `SEAL_URL` и `CHROMIUM`, например:

```bash
SEAL_URL=http://127.0.0.1:5174/dota-spell-letter-hunt CHROMIUM=/путь/к/chromium \
  /tmp/seal-browser-tests/bin/python tests/browser_smoke.py
```

Скриншоты сохраняются в игнорируемый каталог `artifacts/`. Параметр `?test=1` включает только для интеграционных проверок стенды `window.__seal` для боя и `window.__castle` для исследования: снимки состояния, ускоренную прокрутку времени и тестовые фикстуры. В обычном запуске без этого параметра эти отладочные команды не регистрируются.

## Ограничения прототипа

- Боевой отрывок и две комнаты для исследования: без большого мира, подбора предметов, сохранения на диск и многочасовой кампании. Снаряжение в режиме замка пока представлено общим списком состояния.
- Спрайты, окружение, анимации и эффекты оригинальны и процедурны; это цельный прототипный арт, а не профессиональный набор ресурсов от отдельной художественной команды.
- Звуки процедурные; отдельной музыкальной партитуры и озвучки нет.
- Настоящее устройство iPhone/iOS не проверялось. Адаптивная вёрстка и эмуляция мобильного экрана не гарантируют одинаковую производительность и поведение звука во всех версиях Safari.
- Полноэкранный режим зависит от возможностей браузера; системные ограничения iOS могут не разрешать его так же, как на компьютере.

Следующие полезные шаги: проверка на реальных телефонах, настройка сложности по игровым сессиям, ручная полировка кадров спрайтов и расширение окружения без изменения камеры сверху.
